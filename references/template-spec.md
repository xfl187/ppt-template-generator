# Template specification

Use this reference when the user has not fully specified the visual system or layout inventory. These are defaults, not requirements; explicit user direction wins.

## Neutral business defaults

- Format: 16:9 widescreen
- Tone: modern, calm, editorial, and suitable for internal or client-facing business use
- Canvas: warm white or very light neutral with one dark text color, one primary accent, one secondary accent, and restrained semantic colors
- Typography: a widely available sans serif family with clear size and weight contrast; prefer fonts likely to render correctly on the user's platform
- Minimum sizes: approximately 42 pt for deck titles, 32 pt for slide titles, and 17 pt for body text unless the chosen typeface or layout requires a justified adjustment
- Grid: consistent outer margins, a small set of column anchors, and an 8 pt or equivalent spacing rhythm
- Shape language: mostly flat composition with minimal decoration; avoid dashboard-like card grids, excessive pills, and ornamental containers
- Imagery: one coherent photographic or illustrative direction with crops planned for the layout
- Motion: none unless requested

## Default layout catalog

Choose the layouts that demonstrate the system. A broadly useful first version usually contains 10 to 14 slides:

1. Template cover or visual-system overview
2. Title slide
3. Agenda or contents
4. Section divider
5. Title with single-column narrative
6. Two-column text and image
7. Image-led statement or case-study opener
8. Comparison or alternatives
9. Key metric or evidence layout
10. Editable chart layout with clearly labeled sample data
11. Editable table layout
12. Process, timeline, or milestones
13. Quote, testimonial, or key message
14. Closing or contact slide

Remove layouts that do not fit the intended use. Add domain-specific layouts only when the request calls for them, such as a financial summary, product roadmap, research finding, teaching exercise, or portfolio gallery.

## Content conventions

- Give each slide a plain title that identifies what the layout is for.
- Use bracketed placeholders where user replacement is expected, such as `[Presentation title]` or `[Insert image]`.
- Keep example body copy short enough to reveal spacing and hierarchy.
- Label fictional values as sample data, and avoid realistic-looking citations or customer names.
- Use speaker notes only for usage guidance that would clutter the slide.

## Acceptance criteria

A finished template should demonstrate:

- one recognizable visual system across all layouts
- enough compositional range for common presentation needs
- editable text, charts, tables, and diagrams
- reusable image crops and predictable placeholder behavior
- consistent alignment, typography, color, footer, and page-number rules
- no clipped text, overlaps, accidental empty regions, or low-contrast content
- no claim of native Slide Master or `.potx` support unless it was actually created and verified
